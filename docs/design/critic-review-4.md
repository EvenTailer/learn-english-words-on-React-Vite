## 2. ГЛАВНОЕ: четыре пути после неверного ответа

Ключевой сценарий третьего раунда («после неверного ответа первая карточка новой
тренировки показывает чужой вердикт и не отвечается») — **больше не воспроизводится**.
Проверено на живом рендере, все четыре пути.

```
Путь 1 — «Далее»
  неверный ответ  → вердикт «Неверно. Правильный ответ: лев»
                    кнопка «Далее», поле disabled, «Показать ответ» disabled,
                    «Пропустить» disabled, подсказка «Нажмите «Далее», чтобы продолжить»
  «Далее»         → карточка «monkey», вердикта НЕТ, кнопка «Проверить»,
                    поле пустое и активное, подсказка «Впишите перевод и нажмите «Проверить»»

Путь 2 — «Пропустить»
  неверный ответ  → кнопка «Пропустить» disabled (см. примечание ниже)
  «Пропустить»   → клик не срабатывает, состояние не меняется, чужого вердикта нет
  «Пропустить» ДО ответа → карточка «crocodile», вердикта НЕТ, кнопка «Проверить»

Путь 3 — «Сменить»
  неверный ответ  → «Сменить» → экран «Что учим»
  «Начать тренировку» → карточка «лев», вердикта НЕТ, кнопка «Проверить»

Путь 4 — «Выйти»
  неверный ответ  → «Выйти» → главная «Learn English Words»
  «Учить» → «Начать тренировку» → карточка «crocodile», вердикта НЕТ, кнопка «Проверить»
```

Дополнительно:

- **«Показать ответ» после неверного ответа** — кнопка `disabled`, дублирования
  «Неверно. Правильный ответ: крокодил» + «Правильный ответ: крокодил» больше нет.
- **Верный ответ** → «Верно!» → «Далее» → следующая карточка чистая.
- **Код**: `learnSlice.js:30` (`learnStarted` → `verdict = null`),
  `learnSlice.js:60` (`planCleared` → `verdict = null`),
  `learnThunks.js:228` (`skipCard` → `verdictCleared()`),
  `learnThunks.js:238` (`revealAnswer` → `verdictCleared()`),
  `learnThunks.js:180` (`nextCard` → `verdictCleared()`).
- **Тесты**: 111/111 зелёные, из них 3 регрессионных на вердикт
  (`learnThunks.test.js:203`, `:214`, `:225`).

**Примечание про «Пропустить».** После показанного вердикта кнопка «Пропустить»
заблокирована, поэтому путь «неверный ответ → Пропустить → новая карточка» в
интерфейсе недостижим — утечки нет, но и нажать «Пропустить» после ошибки нельзя.
Это осознанное решение (после ответа доступен только «Далее»), избыточный путь
в коде закрыт (`skipCard` сбрасывает вердикт, есть тест). Считаю корректным.

## 4. P1 — мешает

### P1-1. Тост всё ещё наезжает на липкие действия, и теперь перехватывает клик по «Пропустить» (320px)

Замер на 320×700, тренировка, пустой ответ → тост «Вы ничего не ответили»:

```
липкий блок действий : 390..632   (высота 242px, bottom = 68px от низа экрана)
«Проверить»          : 398..454
«Показать ответ»     : 462..510
«Пропустить»         : 526..574
подсказка            : 582..624
тост                 : 550..604   (bottom = 96px от низа экрана)
```

Перекрытия: тост накрывает **нижние 24px кнопки «Пропустить»** и **весь текст
подсказки**. Плюс `.toast` имеет `pointer-events: auto` (у `.toast-wrap` — `none`),
поэтому клик по перекрытой части кнопки уходит в тост:

```
точка (160, 568) — нижняя часть «Пропустить»
document.elementFromPoint → SPAN «Вы ничего не ответили», hitIsToast: true
```

Тост живёт 4.5 с для ошибки (`Toast.jsx:6`) — всё это время нижняя половина кнопки
«Пропустить» не нажимается.

Причина: `--toast-bottom: calc(var(--space-16) + var(--space-8))` = 96px — это
угадывание, а не расчёт. Липкий блок имеет переменную высоту (242px без вердикта,
больше с вердиктом; в одну колонку на ≤420px — больше), а `--bottom-nav-height`
(60px) в режиме фокуса не сбрасывается, хотя нижней навигации во время сессии нет:
из-за этого липкий блок висит на 68px выше низа экрана (мёртвая зона внизу).

**Чинить:** в режиме фокуса тост крепить к верху экрана
(`top: var(--space-4); bottom: auto`) — он ничего не перекрывает; либо считать
высоту липкого блока (`--sticky-actions-height` из JS) и ставить тост над ним.
Отдельно: в `.focus` объявить `--bottom-nav-height: 0`, чтобы липкий блок стоял
внизу, а не висел над пустотой.

### P1-2. Режим «выбор ответа»: после вердикта варианты остаются активными

Для текстового ввода поле заблокировано (`disabled={revealed || Boolean(verdict)}`),
а варианты ответа — нет (`LearnCard.jsx:173`, `disabled={revealed}`).

```
после верного ответа: кнопка «Далее», вердикт «Верно!»
варианты: крокодил (выбран+верен), лев, обезьяна — все enabled
клик по «лев»   → «лев» становится выбранным, зелёный остаётся на «крокодил»
                  карточка одновременно показывает «Верно!» и выделенный «лев»
```

Интерфейс противоречит сам себе, ровно как жаловались в P1-3 третьего раунда —
только для режима «выбор ответа».

**Чинить:** `disabled={revealed || Boolean(verdict)}` для `.choice` — одна строка.

### P1-3. Разнобой H1 на мобильном (спека §2.2)

| Экран | 1440px | 320px | Должно быть |
|---|---|---|---|
| Главная | 32px | 24px | 28px |
| Что учим | 32px | **32px** | 28px |
| Хранилище | 32px | 24px | 28px |
| Наборы слов | 32px | 24px | 28px |
| Добавить слово | 32px | 24px | 28px |

Каждая страница вшивает мобильный H1 отдельно (`--fs-24`), «Что учим» — нет.
Токен `--text-h1-sm: var(--fs-28)` объявлен в `tokens.css:55` и **не используется
нигде** — мобильное правило 28px из спеки не реализовано.

**Чинить:** один токен. В `@media (max-width: 767px)` переопределить `--text-h1:
var(--text-h1-sm)` и убрать локальные `--fs-24` из модулей страниц.

### P1-4. В Хранилище нет H2: H1 (32px) → H3 (20px)

Уровень заголовка перескакивает. Нужен H2 над сеткой или карточки должны быть H2.

### P1-5. Модалка «Добавить в набор» без кнопки создания набора

`AddToListModal.jsx:99-104`: пустое состояние «Своих наборов нет» без действия.
Пользователь из модалки не может создать набор (спека P0-5 `ux-architecture.md`).

### P1-6. Меню темы: `role="menu"` без управления стрелками

5 пунктов `role="menuitemradio"`, фокус после открытия остаётся на `BODY`,
перехода по стрелкам нет, Escape на триггер не возвращает фокус.

### P1-7. В итогах сессии нет списка ошибок

«Отвечено 1 из 1 · 1 Верно · 0 Ошибки · 0 Пропущено · 0 Выучено» — какие слова
были ошиблись/пропущены, непонятно, «Проучить ошибки» нет.

### P1-8. На главной два CTA ведут в одну точку

«Учить слова» (акцентная) → `/learn`; «Начать занятие» → `/learn`; чипы в «Потоке
слов» → `/learn`. Спека §4 требует один блок «Следующее действие».

## 6. Что реально работает (не трогать)

- **Вердикт на карточке.** Правка третьего раунда доведена: сброс во всех четырёх
  путях, блокировка поля/«Показать ответ»/«Пропустить», честная подсказка. Ядро
  приложения больше не ломается после каждого неверного ответа.
- **Мобильная вёрстка.** 320px (мобильная эмуляция) и 310px (узкое окно десктопа
  с классическим скроллбаром): на всех пяти маршрутах `scrollWidth === clientWidth`,
  ни одного элемента за краем.
- **Кнопка удаления** в карточке Хранилища — внутри карточки в обеих ширинах.
- **Контраст.** 5 тем × 5 страниц (24–56 текстовых узлов на страницу) — **0 нарушений AA**.
- **Консоль.** 0 ошибок и 0 предупреждений за весь прогон.
- **Тесты.** 111/111 зелёные (12 файлов), включая 3 регрессионных на вердикт.
- **Сквозные сценарии.** Полный цикл: «Наборы → Мои наборы → Новый набор → Животные»
  → «Хранилище → в набор → Животные» → «Что учим → Мои наборы → Животные (1) →
  Начать тренировку → карточка → «Верно!» → «Далее» → Сессия завершена: Отвечено 1 из 1,
  1 Верно, 0 Ошибок». Хранилище: поиск («Показано 1 из 1» по «tiger»), фильтры, в набор
  (тост «Добавлено в наборов: 1»), удаление (диалог «Удалить слово? “tiger” будет удалён
  из словаря» → «Показано 3 из 3»). «Добавить слово»: дубль → «Слово уже в словаре»,
  новое слово → «Слово добавлено», «Найти в словаре» → перевод «тигр» и ссылка на
  картинку подставились сами, кнопки микрофона присутствуют.
- **1440px.** Контент 1120px, сетка Хранилища 3×341px, страницы не растянуты, читаемо.
