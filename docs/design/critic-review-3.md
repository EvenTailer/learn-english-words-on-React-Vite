## 3. P0 — ломает использование

### P0-1. Вердикт не сбрасывается: первая карточка новой сессии не отвечается и показывает чужой ответ

**Что не так.** Вердикт лежит в Redux (`state.learn.verdict`) и очищается **только** в
`nextCard()` (`learnThunks.js:180`). Но карточку можно сменить тремя другими путями, и
все три оставляют вердикт висеть:

- `skipCard()` → `moveToNextCard` → `startCard` — вердикт не трогают;
- `planCleared()` («Сменить») — вердикт не трогают;
- `learnStarted()` (старт новой сессии) — вердикт не трогают.

`LearnCard` рисует вердикт из `state.learn.verdict` без проверки, к какой карточке он
относится (`LearnCard.jsx:149-164`), а `LearnPage.handlePrimary` при непустом `verdict`
всегда делает `nextCard()` вместо проверки ответа (`LearnPage.jsx:116-123`).

**Замер (сценарий «неверный ответ → Выйти → Учить → Начать тренировку», SPA-навигация).**
```
после неверного ответа:  вердикт = "Неверно. Правильный ответ: лев"
после "Выйти" → "Учить" → "Начать тренировку":
  карточка            = "lion"
  вердикт на карточке = "Неверно. Правильный ответ: лев"   ← про чужую карточку
  кнопка              = "Далее"   (нет "Проверить")
```
Сценарий «неверный ответ → Пропустить» даёт то же самое:
```
после "Пропустить": карточка = "monkey",
                     вердикт  = "Неверно. Правильный ответ: lion",
                     кнопка   = "Далее"
```
Сценарий «неверный ответ → Сменить → Начать тренировку» — то же самое.

**Почему это P0.** Это регрессия ровно на той жалобе, с которой всё началось
(«неправильный ответ не ведёт на следующую карточку»). Теперь неверный ответ
**блокирует следующую карточку**: пользователь не может на неё ответить, кнопка называется
«Далее», и карточка молча выпадает из тренировки. Хуже всего — после «Выйти» и новой
сессии: **после любого одного неверного ответа первая карточка каждой новой тренировки
показывает ложный вердикт и не отвечается**. Это воспроизводится в 100% случаев и
затрагивает ядро приложения.

**Где чинить.** `src/features/learn/learnThunks.js`:
- в `skipCard()` — `dispatch(verdictCleared())` перед `moveToNextCard`;
- в `planCleared` (редьюсер `learnSlice.js:50`) — `state.verdict = null`;
- в `learnStarted` (редьюсер `learnSlice.js:22`) — `state.verdict = null`.

Правильнее — хранить `verdict` вместе с `cardId` и рисовать его только для текущей
карточки (как уже сделано для `lastResult`), тогда чужие вердикты невозможны в принципе.

## 4. P1 — мешает

### P1-1. Тост всё ещё налезает на подсказку под липкими действиями (320px)

Кнопки больше не перекрываются — это главное, P0-1 прошлого раунда по кнопкам закрыт.
Но тост и липкий блок всё ещё пересекаются: тост `top 574 / bottom 628`, блок действий
`390..632`. Под тостом оказывается **подсказка «Впишите перевод и нажмите „Проверить“»**
(кнопки «Пропустить» заканчиваются ровно на 574, тост начинается с 574).

Скриншот `81-toast-320-mobile.png`: красный тост «Вы ничего не ответили» лежит
поверх текста подсказки — текст в тексте.

Причина та же, что и в прошлом раунде, и она не починена: `Toast.module.css` и
`LearnCard.module.css` оба отсчитывают смещение от `--bottom-nav-height` (60px), хотя
во время сессии нижней навигации нет (`--bottom-nav-height` в фокусе не 0).
Тост: `bottom = 60+12 = 72px`, липкие действия: `bottom = 60+8 = 68px`.

**Чинить:** один токен `--safe-bottom` (в фокусе = `--space-2`, вне фокуса =
`--bottom-nav-height + --space-2`), как и предлагалось в прошлом раунде.

### P1-2. Хранилище на 320px: кнопка удаления вылезает за карточку

Сетка починена (`minmax(0, 1fr)`, карточка 16..294), но внутри карточки подвал
`WordCard.module.css:122` (`.footer`, `display:flex; justify-content:space-between`)
не влезает: `.score` («0/5 по расписанию», перенос на 2 строки) не даёт ужиматься,
`.actions` (152px) выталкивается вправо.

```
карточка:  l 16,  r 294
.actions:  l 167, r 319   ← на 15px за карточкой, в 1px от края экрана
```
На узком окне десктопа (классический скроллбар, ширина 310) это даёт
`scrollWidth 319 > clientWidth 310` — горизонтальная прокрутка на 9px. На телефоне
(оверлейный скроллбар, 320px) прокрутки нет, но кнопка висит за рамкой карточки
(`80-storage-320-mobile.png` — корзинка нарисована за правым бордюром карточки).

**Чинить:** `.footer { flex-wrap: wrap }` + `.score { min-width: 0 }` + `.actions { flex: none }`,
либо перенести кнопку удаления в шапку карточки.

### P1-3. После неверного ответа интерфейс противоречит сам себе

После вердикта «Неверно»:
- подсказка по-прежнему «Впишите перевод и нажмите **„Проверить“**», а кнопка уже «Далее»;
- поле ввода осталось **активным** — можно печатать, но проверить нечем;
- «Показать ответ» осталось **активным** → если его нажать, на карточке оказывается
  «Неверно. Правильный ответ: крокодил» **и** «Правильный ответ: крокодил» — один и тот
  же ответ дважды (`63-reveal-after-wrong.png`).

**Чинить:** после вердикта гасить подсказку («Ответ выше — нажмите „Далее“»), блокировать
поле, прятать «Показать ответ».

### P1-4. «Мои наборы»: три залитые акцентом кнопки, две из них делают одно и то же

```
Создать набор   rgb(79,70,229)   ← заголовок страницы
Новый набор     rgb(79,70,229)   ← кнопка в шапке, handleCreate
Создать набор   rgb(79,70,229)   ← кнопка в пустом состоянии, handleCreate
```
«Новый набор» и «Создать набор» — один и тот же обработчик. Спека требует одну
акцентную кнопку на экран. Плюс до конца не вычищено слово «список»: «Своих списков
пока нет», «Название списка», «Своих списков нет» (модалка), «Слова из этого списка
попадут в тренировку» (LearnSetup) — при том, что вокруг уже «набор».

### P1-5. На главной два CTA ведут в одну точку, «Поток слов» — туда же

«Учить слова» (акцентная) → `/learn`; «Начать занятие» → `/learn`; чипы «lion/monkey/
crocodile» в «Потоке слов» → `/learn` (экран выбора, не карточка слова). Спека §4
требует один блок «Следующее действие» и ноль вторых кнопок в ту же точку.
