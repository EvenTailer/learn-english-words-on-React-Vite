## 3. P0 — ломает использование

### P0-1. Тост ответа наезжает на кнопки тренировки на 320px

**Что не так.** `Toast.module.css`:
```css
@media (max-width: 767px) {
  .toast-wrap { bottom: calc(var(--bottom-nav-height, 68px) + var(--space-3)); }  /* 72px */
}
```
`LearnCard.module.css`:
```css
@media (max-width: 767px) {
  .actions { position: sticky; bottom: calc(var(--bottom-nav-height) + var(--space-2)); }  /* 68px */
}
```
Оба отсчитывают от **нижней навигации**, но во время сессии нижней навигации **нет**
(режим фокуса: `navPresent: false`). В итоге тост (72px) и липкий блок действий (68px)
оказываются в одной зоне, а фон тоста — `danger-soft` = `rgba(244,63,94,0.16)`, **16 % непрозрачности**,
поэтому текст под ним просвечивает.

**Замер (320×700, тёмная тема, ответ «lion» на «лев»).**
- тост: `top 539, bottom 628`
- `.actions`: `top 385, bottom 627` → `toastOverActions: true`
- `.actions` не перекрывает «Проверить» (393–449), но перекрывает **«Пропустить»** и подсказку
  «Впишите перевод и нажмите „Проверить“».

На скриншоте `32-toast-320.png` видно, как «Неверно. / Правильный ответ: / lion» ложится
поверх «Пропустить» и поверх подсказки — текст в тексте, читать нечего.

**Где чинить.**
- `src/shared/ui/Toast.module.css` — смещение тоста в режиме фокуса.
- `src/widgets/LearnCard/LearnCard.module.css` — `.actions` в режиме фокуса должен липнуть к
  `var(--space-2)` (8px), а не к высоте невидимой нижней навигации.
- Чинить через «общий токен» (например, `--safe-bottom`, который в фокусе = 8px, а вне фокуса =
  `bottom-nav-height + 8px`), а не двумя независимыми формулами.

**Почему это P0.** Это ровно тот момент, ради которого пользователь жаловался: после нажатия
«Проверить» экран превращается в кашу из наложенных текстов. И это происходит ровно в тот
момент, когда нужно прочитать правильный ответ.

### P0-2. Регрессия: Хранилище переполняется по горизонтали на 320px

**Что не так.** Правка №3 заменила короткую подпись «верных» на длинную «из 5 по расписанию»
и растянула минимальную ширину карточки. `StoragePage.module.css`:
```css
@media (max-width: 560px) {
  .grid { grid-template-columns: 1fr; }   /* ← не minmax(0, 1fr) */
}
```
`1fr` = `minmax(auto, 1fr)`, а `auto` у грид-элемента = его min-content. Min-content карточки
стал 305px → трек стал шире контейнера → карточка вылезла за экран.

**Замер (320×700, тёмная тема).**
```
documentElement.scrollWidth = 321   clientWidth = 320     ← горизонтальный скролл
.grid: l 16, r 304, w 288, gridTemplateColumns = "305.281px"   ← трек шире контейнера
article: l 16, r 321, w 305                                     ← выходит за правый край
.scoreLabel "из 5 по расписанию": w 79, h 42 (3 строки)
```
Видно на `46-storage-320-bottom.png`: карточка слова обрезана справа, кнопка удаления
висит на краю экрана, а подпись «0 из 5 по расписанию» разложилась на три строки рядом с
цифрой «0».

**Где чинить.**
- `src/pages/StoragePage.module.css` → `.grid { grid-template-columns: minmax(0, 1fr); }`
  (спека §4.5 прямо требует `minmax(0, 1fr)`).
- `src/widgets/WordCard/WordCard.module.css` → `.score` / `.scoreLabel`: не давать подписи
  ломать ширину (`min-width: 0`, `white-space: nowrap` на «из 5» + перенос «по расписанию»,
  либо короче: «0 / 5» с подписью «по расписанию» в одну строку).

**Почему это P0.** Это регрессия, внесённая текущим коммитом: раньше на 320px Хранилище
не переполнялось. Плюс текст в три строки на карточке — визуальный мусор.

## 4. P1 — мешает

### P1-1. Тост squeezed до 160px на 320px

`Toast.module.css`:
```css
.toast-wrap { position: fixed; left: 50%; transform: translateX(-50%); max-width: min(92vw, 34rem); }
```
У `position: fixed` с `left: 50%` и без `right` ширина по контентной части = **viewport − 50 %**,
то есть 160px при 320px. `max-width: 92vw` (294px) тут бессилен — контейнер уже 160px.
Сообщение «Неверно. Правильный ответ: крокодил» укладывается в три строки и налезает
на крестик.

**Замер:** `toast l 80, w 160` при `clientWidth 320`. Скриншот `32-toast-320.png`.

**Чинить:** `.toast-wrap { left: 50%; width: max-content; max-width: min(92vw, 34rem); }`
либо `inset-inline: 0; margin-inline: auto; width: fit-content;`.

### P1-2. Вердикт «верно/неверно» не рисуется ни разу

Правка `lastResult.cardId` сняла симптом, но убила обратную связь целиком.

`checkAnswer` в `src/features/learn/learnThunks.js` **сразу** вызывает `moveToNextCard` — и
на ответ, и на ошибку. React батчит `setLastResult` и `dispatch(checkAnswer())` в один рендер,
поэтому `LearnCard` получает `card = следующая карточка`, а `lastResult.cardId = предыдущая`.
Условие `lastResult.cardId === card.id` → `false` → `result = null` → `resultClass = ''`.

**Замер (после «Проверить» с неверным ответом и после верного):**
```
shell class = "_shell_1itec_10"     hasCorrect: false    hasWrong: false
shell class = "_shell_1itec_10"     hasCorrect: false    hasWrong: false
```
Классы `.shell.correct`, `.shell.wrong`, `.choiceCorrect`, `.choiceWrong` и вся логика
`resultClass` / `choiceClass` — **мёртвый код**.

**Чинить (по §3.6 спеки):** не переключать карточку сразу. Показывать вердикт **на карточке**
и ждать кнопки «Дальше»:
- неверно → рамка `--danger-border`, блок «Неверно. Правильный ответ: X»;
- верно → рамка `--success-border`, блок «Верно»;
- `aria-live="polite"` на блоке вердикта;
- карточка переключается по «Дальше» (или по Enter).

Это же автоматически закрывает P0-1: правильный ответ перестаёт жить в тосте.

### P1-3. Учебное слово всё ещё 32px, а кнопка «Проверить» перекрикивает вопрос

Спека §3.2 ставит слово на **ранг 1** и требует 40px (32px на мобильном). Сейчас:
```
1440px: h2.word = 32px / 700
 320px: h2.word = 28px / 700
```
Ровно тот же размер, что у H1 страницы. При этом «Проверить» — единственная залитая
акцентом кнопка и глаз идёт на неё, а не на вопрос. Спека требует «слово главнее картинки» —
картинка это уже починила (128/96px), но главным элементом слова всё ещё не является.

**Чинить:** завести роль `--text-word: 40px` (`--text-h1-sm` → 32px на мобильном) и
применить в `LearnCard.module.css` `.word`.

### P1-4. «Выйти» и «Сменить» — 39px по высоте

`LearnCard.module.css` `.exitButton` → `padding: var(--space-2) var(--space-3)`, `font-size: 14px`
→ **68×39** и **83×39**. Спека `--tap-min: 44px`. Раньше была одна такая кнопка, теперь их две.
На 320px это единственные мелкие цели на карточке.

**Чинить:** `min-height: var(--tap-min)` в `.exitButton` (или общий класс для
второстепенных кнопок карточки).

### P1-5. «Набор» и «список» — по-прежнему шесть названий одного объекта

Вкладка «Мои наборы» → заголовок **«Мои списки»** → пустое состояние **«Своих списков пока нет»** →
кнопки **«Новый список»** и **«Создать список»** → модалка **«Добавить в список»** →
текст в модалке **«Создайте список на странице „Наборы“»**. Шесть имён на одном экране.
Плюс `aria-label` карточки слова: «Добавить crocodile в список».

**Чинить:** одно слово «набор» везде (`plan.js`, `MyLists.jsx`, `AddToListModal.jsx`,
`WordCard.jsx`, `AddPage.jsx`).

### P1-6. H2 = 20px на главной и 18px в «Что учим» вместо 24px

Спека §2.1: `--text-h2` = 24px, и там прямо названы «Поток слов» и «Цель на сегодня».
Фактически:
```

Что учим: h2 «Источник» 18px, «Направление» 18px, «Формат ответа» 18px, «Сколько слов» 18px
```
Плюс `LearnSetup.module.css` использует сырые `--fs-32 / --fs-18 / --fs-14` вместо
ролевых `--text-*` (нарушение §2.2, правило 1).

### P1-7. Два CTA на главной ведут в одно место; чипы «Потока слов» — ложный аффорданс

## 8. Вердикт

**Пока отдавать пользователю нельзя — но почти можно.** Три правки (P0-1, P0-2, P0-3)
закрывают всё, что человек видит в первые пять секунд на телефоне, и стоят вместе около
часа работы.

Что изменилось по сравнению с прошлым отчётом: приложение перестало выглядеть как
черновик — шрифт, ширина, тёмная тема и карточка тренировки теперь выглядят как продукт.
Претензия «ужасный дизайн» в части «шрифт и ширина» закрыта полностью. Жалоба
«неверный ответ не ведёт на следующую карточку» закрыта по симптому, но при этом исчезла
обратная связь на карточке — её надо вернуть (P1-2). Жалоба «выучено после 5 верных»
закрыта по цифре, но подпись «из 5 по расписанию» сломала вёрстку Хранилища на 320px
(P0-2) и не показывает, когда следующий повтор (P2-4).

Открытых пунктов: 3 × P0, 8 × P1, 22 × P2. Из старых 23 P0/P1 закрыто 4 полностью
и 3 частично, одно (P0-2, ширина) — формально, но с отступлением от спеки.
