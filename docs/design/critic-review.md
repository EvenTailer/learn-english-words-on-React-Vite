## 3. P0 — ломает использование

### P0-1. `--font-sans` и `--font-mono` не существуют → всё приложение рисуется Times New Roman

**Что не так.** В `src/styles/tokens.css` нет определений `--font-sans` и `--font-mono`. В `tokens.css:378` стоит `font-family: var(--font-sans)`. Неопределённый `var()` делает правило невалидным → `font-family` наследуется → всё приложение получает шрифт по умолчанию браузера. На Windows Chrome это **Times New Roman**.

**Где.**
- `src/styles/tokens.css` — определить `--font-sans` и `--font-mono` в `:root`.
- `src/styles/tokens.css:378` — `body { font-family: var(--font-sans) }`.
- `src/widgets/LearnCard/LearnCard.module.css:138` — `.phonetic { font-family: var(--font-mono) }`.
- `src/widgets/WordCard/WordCard.module.css:75` — `.phonetic { font-family: var(--font-mono) }`.

**Замер.** `getComputedStyle(document.body).fontFamily` → `"Times New Roman"` на всех пяти маршрутах, в обеих темах. На скриншоте главной и карточки сессии видно засечки во всех заголовках, кнопках и полях.

**Что сделать.** Дописать в `:root`:
```css
--font-sans: system-ui, -apple-system, 'Segoe UI', Roboto, 'Helvetica Neue', Arial, sans-serif;
--font-mono: ui-monospace, SFMono-Regular, 'SF Mono', Menlo, Consolas, 'Liberation Mono', monospace;
```
Это ровно тот «системный стек», который дизайн-система обещала в комментарии к токенам, но который никто не вписал. Одной правкой чинится вся жалоба №1 в части «выглядит как мусор».

### P0-3. Вердикт «неверно» надевается на следующую карточку, правильный ответ теряется

**Что не так.** `lastResult` в `LearnPage.jsx` живёт в `useState` и гаснет по таймеру 800 мс, но **не сбрасывается при смене карточки**. `LearnCard` вешает `styles.wrong` на `<Card>` — то есть на ту карточку, которую открыли следующей. Пользователь видит, как только что не отвеченное слово подсвечивается красной рамкой «ошибка». Правильный ответ при этом существует только в тосте на 4.5 с, а на карточке уже другое слово.

**Где.**
- `src/pages/LearnPage.jsx` — `const [lastResult, setLastResult] = useState(null)` и эффект с `RESULT_HIGHLIGHT_MS = 800`.
- `src/widgets/LearnCard/LearnCard.jsx` — `resultClass` на `<Card className={...}>`.
- `src/features/learn/learnThunks.js` — ветка «неверно» с `toastShown({ message: 'Неверно. Правильный ответ: ...' })` и немедленным `moveToNextCard`.

**Замер.** Ответ «zzz-not-the-answer» на «лев»: карточка сменилась на «monkey», но класс `_wrong_...` на ней присутствует; через 900 мс исчезает. Тост: «Неверно. Правильный ответ: lion» — при слове на карточке «monkey».

**Что сделать.**
1. Сбрасывать `lastResult` при смене карточки: `useEffect(() => setLastResult(null), [currentCardId])`.
2. Показывать вердикт в самой карточке до перехода, как в сценарии A5 спеки `ux-architecture.md` §2: подсветить правильный ответ на карточке, кнопка «Дальше». Тогда верный ответ не исчезает через 4 секунды.
3. Если мгновенный переход нужен — перенести «правильный ответ» из тоста в постоянный блок вердикта, а не в `aria-live`-тост.

### P0-4. Счётчик «N верных» противоречит бейджу «в процессе»

**Что не так.** `StoragePage` передаёт в карточку `progress.correct` — это **общее число верных ответов**. А статус «выучено» считается по `progress.streak` — по **ответу с интервалом**. Это разные числа, и интерфейс показывает первое, а статус — по второму. Итог: у слова 5 верных ответов подряд (в разные дни), а карточка показывает «5 верных» с бейджем «в процессе».

**Где.**
- `src/pages/StoragePage.jsx` — `correct={progress?.correct ?? card.count ?? 0}`.
- `src/widgets/WordCard/WordCard.jsx` — блок `.score` («N верных»).
- `src/features/progress/progressSlice.js` — `status`/`masteredAt` по `streak`, `correct` — отдельный счётчик.
- Тест `src/features/progress/progressSlice.test.js` («повтор в тот же день не засчитывается в серию») фиксирует ровно это расхождение: `streak = 1`, `correct = 2`.

**Что сделать.** Показывать прогресс освоения, а не общий счётчик: «3/5 по расписанию» + «следующий повтор через 2 дня». Если нужен и общий счётчик — подписать его иначе («ответов: 7»), чтобы не путать с прогрессом к «выучено». Без этого жалоба №3 формально закрыта, а по ощущениям — нет.

## 6. Приложение: сводные замеры

**Токены (проверено в браузере через `getComputedStyle(document.documentElement)`):**

| Токен | Значение | Последствие |
|---|---|---|
| `--page-max` | пусто | `max-width: none` на всех страницах и в шапке |
| `--font-sans` | пусто | `body` → Times New Roman |
| `--font-mono` | пусто | транскрипция → Times New Roman |
| `--fs-48` | пусто | «404» без увеличения |
| `--bottom-nav-height` | `60px` | в порядке (было рассинхронизировано — исправлено) |

**Ширины (1440×900):** контейнер страницы 1440px / `max-width: none`; шапка 1440px от края; колонки главной `320px 1032px`.

**320×700:** переполнение по горизонтали — на главной (полоса метрик, `scrollWidth 482` при `clientWidth 288`, видна 1 плитка из 3); на остальных страницах переполнения нет. Модальные окна — 288px, вписываются.

**Карточка сессии:**
- 1440px: верхняя строка — «Выйти» (иконка 48 + текст 66) · бейдж 75 · «Сменить» 48; слово 32px; картинка 128×128.
- 320px: «Выйти» 122px · бейдж 75px · «Сменить» **33×48**; поле ответа 254×56; «Проверить» 254×56 (sticky снизу, виден без скролла — `docH 700` = `viewportH 700`).

**Доступность:** контраст — 0 нарушений AA на 5 страницах в тёмной и светлой темах; у всех кнопок есть доступное имя; у всех изображений есть `alt`; `aria-current` на активном пункте; `lang="ru"`; ловушка фокуса в модалке работает; ошибок в консоли нет; 108/108 тестов зелёные.

**Не проверено вживую (только по коду):** Voice Input (нужен микрофон), 5 тем оформления (проверены только тёмная и светлая), реальная работа с сетью на странице «Добавить» (запрос в словарь).
