## 0. Главная мысль

Экран должен отвечать на вопрос **«что нажать, чтобы слово попало в словарь»**, а не «сколько тут полей».

Четыре правила, из которых выводится вся остальная спецификация:

1. **Одно главное действие, и оно переезжает.** Пока слово не найдено — главное действие «Найти в словаре». Слово найдено или перевод введён руками — главное действие «Добавить в словарь». Залитой (`--accent-solid`) на экране всегда **ровно одна** кнопка (антипаттерн A1 в `visual-system.md` §6).
2. **Найденное показываем там, где смотрят.** Перевод, произношение, определение и картинка появляются **под полем, в потоке формы** — там, куда человек только что вписал слово.
3. **Правая колонка отвечает на вопрос «что сохранится».** Не «как это будет выглядеть», а список полей с их фактическими значениями. Справа — чек, а не украшение.
4. **Ошибка всегда на экране и всегда с повтором.** Тост — только для подтверждения успеха (и то не всегда).

Порядок работы человека: **слово → поиск → проверка перевода → (необязательно) набор → сохранить**.
Картинка, пример, часть речи — вторично.

переезжает с «Найти в словаре» на «Добавить в словарь» — как лампочка, которая переключается.

### 3.2. Порядок блоков и их вес

| № | Блок | Вес | Показывается |
|---|---|---|---|
| 0 | Заголовок + лид | Крупно | всегда |
| 1 | **Слово** — поле, микрофон, «Найти в словаре» | Крупно | всегда |
| 2 | **Перевод** — поле, микрофон, найденные данные | Крупно, вторично по тону | всегда; блок «Слово найдено» — после успеха |
| 3 | **Набор** — чипы + «Создать набор» | Мелко (label 14px, чипы) | всегда |
| 4 | **Своя картинка** — раскрывающийся блок | Мелко, свёрнут | всегда (свёрнут), раскрыт — по запросу |
| 5 | **Действия** — «Добавить в словарь» + подпись + «Очистить» | Крупно (залитая кнопка 56px) | всегда |
| П | **Что сохранится** — колонка 320px, sticky | Средне | ≥1024px; на мобильном — после формы |

Иерархия: `--text-h1` 32/28px · заголовок блока `--text-h3` 20px · подпись поля `--text-label` 14px ·
микротекст 14px `--text-3`. Залитых кнопок — одна.

### 3.3. Кто главный прямо сейчас

| Ситуация | «Найти в словаре» | «Добавить в словарь» | Пояснение под кнопкой |
|---|---|---|---|
| Пусто | **залитая**, активна | серая, disabled | «Слово попадёт в словарь и в тренажёр.» |
| Введено слово, поиск не запускали | **залитая**, активна | серая, disabled | то же |
| Идёт поиск | спиннер, disabled | серая, disabled | статус под полем: «Ищем «sunflower» в словаре…» |
| Найдено | вторичная, активна | **залитая**, активна | «Слово попадёт в словарь и в тренажёр.» |
| Перевод введён руками | вторичная | **залитая**, активна | то же |
| Набор выбран | вторичная | **залитая**, активна | «Слово попадёт в словарь, в тренажёр и в набор «Еда».» |
| Ошибка сети / не найдено | **залитая**, активна (повтор) | серая, disabled | — |
| Слово уже есть | вторичная | вторичная «Обновить перевод» | — |
| Успех | — | — | форма заменена панелью успеха |

Реализация «одной залитой кнопки»: `variant` у «Найти в словаре» = `primary`, пока
`!found && !russianWord`; иначе `secondary`. «Добавить в словарь» = `primary`, когда
`englishWord && russianWord` (или слово уже есть и выбран набор); иначе `secondary` + `disabled`.

- Жёлтый блок (`--warning-soft` + `--warning-border`, `role="alert"`): иконка + заголовок + текст + две кнопки (§4.2).
- «Ввести перевод» ставит фокус в поле «Перевод» и переводит форму в ручной режим.
- Правая колонка: Слово ✓, Перевод —, остальные —.
- Тост не показывать.

### 5.5. Ошибка сети

- Красный блок (`--danger-soft` + `--danger-border`, `role="alert"`), по образцу `visual-system.md` §5.6: иконка + текст + secondary-кнопка «Повторить».
- Текст не содержит «ошибка произошла» — что случилось и что делать.
- Форма не сбрасывается: введённое слово остаётся.
- Сейчас ошибка уходит в тост (`AddPage.jsx:152-162`) — убрать тост, читать `state.dictionary.error`.

### 5.6. Слово уже есть

- Жёлтый блок «Слово уже есть» с двумя кнопками.
- «Обновить перевод» перезаписывает перевод существующей карточки. **Требует правки `wordsSlice.cardAdded`** — сейчас он молча выходит при дубликате (баг B6 в `microcopy-and-qa.md`).
- Тост «Слово уже в словаре» убрать — состояние на экране.

### 5.7. Успех

- Форма заменяется панелью успеха (§4.4). Тост «Слово добавлено» **не** показывать: по решению проекта (`critic-review-4`) вердикт живёт на карточке, а не в тосте.
- «Добавить ещё» очищает форму и возвращает фокус в поле «Английское слово».
- «Открыть в словарь» → `/storage`.

## 6. Мобильный (320px)

Замеры: при 320px `document.documentElement.scrollWidth === 320` — горизонтального скролла нет,
и он не должен появиться.

### 6.1. Что видно на первом экране (320×568)

1. Шапка приложения (56px).
2. h1 «Добавить слово» — `--text-h1-sm` 28px.
3. Лид в 2–3 строки — на 320px берём `--text-body` 16px.
4. Поле «Английское слово» — 56px, крестик очистки справа.
5. Иконка микрофона 48×48 справа от поля.
6. Подпись «Нажмите микрофон — и продиктуйте слово.» (14px, 2 строки).
7. **Залитая кнопка «Найти в словаре»** — 56px, во всю ширину.

Итого ≈ 330px контента — в первый экран помещается с запасом.
На первом экране **не** должно быть: перевода, набора, картинки, панели «Что сохранится» и превью.

### 6.2. Правила мобильного режима

| Правило | Значение |
|---|---|
| Колонок | 1. Панель «Что сохранится» — **после** формы, не сверху. Сейчас `.preview { order: -1 }` ставит её первым — на 320×568 человек видит превью «sunflower / подсолнух» вместо своей формы. Отступление от `visual-system.md` §4.3 («превью 100% сверху») — сознательное: пустой чек над формой бесполезен, а ответ на «что сохранится» нужен после ввода |
| Главное действие | `position: sticky; bottom: calc(var(--bottom-nav-height) + var(--space-2))` — приём из `LearnCard.module.css:300-307`. Сейчас кнопка на 320×568 находится на `top=1166` при высоте экрана 568 — на два экрана ниже |
| Отступ снизу страницы | `padding-bottom: calc(var(--bottom-nav-height) + env(safe-area-inset-bottom) + var(--space-8))`, чтобы sticky-панель не перекрывала последний блок |
| Поля | Высота 56px (не 48). `Input.module.css` жёстко задаёт 48px — нужен модификатор высоты |
| Кнопки | Главная 56px, вторичные 44px, отступ 8px (`--tap-min` 44) |
| «Очистить» | Во всю ширину, под главной кнопкой, ghost |
| Чипы наборов | `flex-wrap`, тап-таргет ≥44px. Много наборов — первые 4 и «Ещё N» |

| Правая колонка | Полная ширина, строки в одну колонку, значения по левому краю (на 320px разница колонок съедает ширину) |
| Блок «Своя картинка» | Свёрнут; превью 96px (не 120px) |

- Превью карточки в отдельной колонке.
- Строку «Источник: …» целиком — только «Картинка: Wikimedia Commons» с переносом.
- Длинные определения без ограничения.

## 11. Чек-лист приёмки

- [ ] В любой момент на экране **ровно одна** залитая кнопка (замер: `primary buttons` содержит один элемент).
- [ ] Без инструкции: ввести слово → «Найти в словаре» → увидеть перевод → «Добавить в словарь». Больше ничего нажимать не нужно.
- [ ] Enter в поле слова запускает поиск (а не отправку формы) — проверяется настоящим нажатием клавиши.
- [ ] Браузерных пузырей нет; все ошибки на русском, на экране, в стиле приложения.
- [ ] Правая колонка называется «Что сохранится», заголовок 24px, показывает фактические значения, а не «sunflower / подсолнух».
- [ ] Подпись под главной кнопкой объясняет последствие.
- [ ] Блок «Своя картинка» свёрнут; картинка из словаря — в блоке «Слово найдено» с подписью источника.
- [ ] Микрофоны имеют видимые подписи.
- [ ] Часть речи по-русски; альтернативные переводы видны и кликабельны.
- [ ] Дубликат даёт экранное состояние «Слово уже есть», а не тост «Слово добавлено».
- [ ] 320px: горизонтального скролла нет (`scrollWidth === 320`); на первом экране видны заголовок, поле слова, микрофон и залитая «Найти в словаре»; «Добавить в словарь» липнет к низу и видна всегда.
- [ ] 1440px: колонка 720px + панель 320px, обе в пределах `--layout-content`, поля ≥32px.
- [ ] В модулях нет `var(--fs-*)` и нет медиазапросов с 480/560/767/900.
